How the cost was measured

Two tracks, because one of them alone lies to you.

Track A — real code

The same edit session, on every file

Ten large files per entry (median ≈ 2,000 lines) from a flagship open-source project. Each is priced through one identical unit of agent work on a fixed 300-line slice: one full read, two 120-line focused re-reads, a 60-line search digest, two 12-line diff hunks, and a 40-line span of new code.

Track B — same work

140 tasks, implemented in all of them

Track A can't tell you whether a language spent more tokens doing more. So every language is also measured on 140 Rosetta Code tasks present in at least 36 of 48 languages, each cost expressed as a ratio to that task's cross-language median and combined with a geometric mean. That index is what the ranking uses.

Tokenizer

o200k_base, and it barely matters

Claude's tokenizer isn't public, so the GPT-4o BPE stands in. Re-running the whole survey on cl100k_base reproduces the language ranking at ρ = 0.999, and how tokenizer-friendly a language is predicts nothing about where it lands.

Per-line density is the wrong metric. Languages with cheap lines need more of them, so the number everyone reaches for is slightly anti-correlated with real cost. What predicts an agent's token bill is how few lines a language needs — expressiveness, not punctuation.

What the numbers say

EXPRESSIVENESS

Fewer lines, not friendlier syntax

Go's lines are unremarkable — 9.5 tokens each. It costs 1.48× Python for the same work because it needs 31.8 lines where Python needs 16.6. Assembly and Python sit at opposite ends of tokenizer friendliness and that fact predicts neither one's rank.

MAINSTREAM SPREAD

About 1.7× between the languages most people use

For identical functionality: Ruby 0.77×, Python 1.00×, TypeScript 1.17×, Rust 1.21×, Java 1.30×, C# 1.33×, Go 1.48×, C++ 1.55×, C 1.69×. Real, but smaller than the gap between a well-scoped prompt and a lazy one.

COMMENTS

A quarter of the bill is prose

Across the language corpus, a median 23% of a file's tokens sit in comment lines — larger than the gap between most adjacent ranks, and the one lever a team controls without changing language.

FRAMEWORKS

Framework choice is mostly language choice

The whole framework table spans 1.6×, against 2.1× across languages. Every TypeScript framework lands in 7.0–11.0 tokens per code line, every PHP one in 9.0–10.6. A framework's own contribution rarely exceeds ±25%.

LEGACY

Old stacks cost twice

COBOL (2.5×) and Assembly (3.8×) are the most expensive per unit of functionality and produce the largest files, so an agent burns its context faster and has less room left to reason in. VBA, Visual Basic .NET and Delphi cluster around 1.38×.

PRACTICAL

What to do with this

Not "rewrite in Ruby". Use it when the choice is already close, when budgeting agent runs against a large codebase, and as a reason to be ruthless about dead comments and generated files sitting in the context window.

Before you quote these numbers

Sampling limits
  • One repository per entry (two for a few). House style — line width, comment culture, formatter settings — moves the Track A columns by more than the gap between neighbouring ranks. The Rosetta axis, which the ranking uses, doesn't have this problem.
  • Rosetta Code is not production code. Tasks are small and algorithmic; the corpus under-represents the glue, error handling and I/O that dominate real work. It is used only for relative cost between languages on identical work.
  • Small samples: COBOL, R and SQL yielded only 6 qualifying large files each; COBOL has no edit-session figure because none of its files reached 300 lines.
  • MicroPython shares Python's task corpus — they are the same language on that axis. Their real-code rows are genuinely different corpora.
What was excluded, and why
  • Data files, by a uniform mechanical rule: dropped if more than 60% of lines are under 35% letters, or more than 10% of characters are non-ASCII, or (non-markup only) the file exceeds 20 tokens per code line. This removes locale tables, coefficient blocks, generated arity boilerplate and inline SVG — which otherwise distort per-line figures by 2–5×.
  • Bundled third-party libraries where a project vendors them into its own tree under a non-obvious path. Six of WordPress's ten largest files were copies of getID3, PHPMailer and sodium_compat.
  • Tests, fixtures, minified and generated output, except where a project's only substantial code lives there.
Roster provenance
  • The Stack Overflow survey page is blocked by this sandbox's network egress policy, so the roster of languages and frameworks was reconstructed from the survey's published technology categories. A handful of low-share entries are absent.
  • Percentages and shares from the survey are not used anywhere in the measurement — the survey only decides which languages and frameworks are on the list.
